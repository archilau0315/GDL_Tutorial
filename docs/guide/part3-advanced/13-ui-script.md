# 第 13 章 UI 脚本与参数界面

> 图号 GDL-13 · 精通篇 · 阅读约 30 分钟 · 含沙盒练习

## 本章目标

- 分清「参数列表 / 参数脚本 / UI 脚本」三层各管什么
- 用 `VALUES` 限制取值范围，用 `PARAMETERS` 做联动，用 `LOCK` / `HIDEPARAMETER` 收拾界面
- 用 `UI_DIALOG` + `UI_PAGE` + 控件的结构，把参数排成一张能看懂的面板
- 明白沙盒的边界：它只有脚本变量，没有参数表，也没有对话框

## 三层：变量 → 参数 → 界面

| 层 | 在哪定义 | 管什么 | 写错的后果 |
|---|---|---|---|
| 参数列表 | 库部件编辑器 → 参数表 | 名字、类型、默认值 | 3D 脚本读到的值不对 |
| 参数脚本 | 参数脚本页 | 取值范围、联动、显隐 | 用户能填出把模型撑坏的数字 |
| UI 脚本 | UI 脚本页 | 控件怎么摆、放第几页 | 功能都在，但没人找得到 |

一句话：**参数列表是数据，参数脚本是规则，UI 脚本是排版。**

沙盒里没有参数表，像 `w = 1.2` 这样的赋值直接写在 3D 脚本第一行。回到 Archicad，这几行就变成参数的默认值，脚本读的是参数而不是写死的数。

## 参数列表：先把名字起好

| 列 | 例子 | 注意 |
|---|---|---|
| 变量名 Variable name | `w` | 脚本里引用它；改名会牵连所有脚本，定了别动 |
| 描述名 Descriptive name | 总宽 | 对话框显示的就是它，做中文对象就填中文 |
| 类型 Type | Length | 长度自动带项目单位，别用 Real 冒充 |
| 默认值 | 1.20 | 新插入对象时的初始尺寸 |

三条经验：

1. 变量名用短英文（`w` / `d` / `h`），描述名写中文全称，脚本和界面都不别扭
2. 尺寸参数选 `Length`，Archicad 会按 毫米/米 自动换算；用 `Real` 就得自己管单位
3. 参数超过 10 个就分前缀，`doorW` / `winW` / `mat`，后面 UI 脚本排版才不会乱

## 参数脚本：给取值上锁

参数脚本在打开设置对话框之前、以及每次参数被改动之后运行，所以只做轻量的校验和联动，别在里面建几何。

```gdl
! 参数脚本 / parameter script
VALUES "w" 0.6, 3.0, 0.05                  ! 最小值, 最大值, 步长
VALUES "n" 1, 6, 1                         ! 整数步长 1
VALUES "doorType" "单扇", "双扇", "推拉"    ! 字符串候选，界面上变下拉

IF w < 0.9 THEN
  VALUES "n" 1, 2, 1                       ! 窄柜只允许 1~2 扇门
ENDIF

PARAMETERS h = w * 0.75                    ! 联动：h 跟着 w 算，界面表现为只读
LOCK "h"                                   ! 再锁一道，防止被改
HIDEPARAMETER "n"                          ! 内部参数，列表里不显示
```

| 语句 | 作用 | 用户看到什么 |
|---|---|---|
| `VALUES` | 限定范围或候选值 | 输入框有上下限，字符串变下拉 |
| `PARAMETERS x = ...` | 由别的参数推导 | 每次运行都重算，手改无效 |
| `LOCK` / `UNLOCK` | 锁定 / 解锁 | 输入框变灰 |
| `HIDEPARAMETER` | 从参数列表隐藏 | 完全不出现，但脚本仍能用 |

`PARAMETERS` 和 `LOCK` 别混：前者是「这个值由公式决定，每次重算」，后者是「用户不许改，但脚本里还能自己赋值」。要公式驱动就写 `PARAMETERS`，只是不想让人碰就写 `LOCK`。

## UI 脚本：把参数排成面板

Archicad 25 起，库部件编辑器多了 UI 脚本页，可以用命令画自定义设置面板，替代默认那串又长又平铺的参数列表。结构只有三层：对话框 → 页签 → 控件。

```gdl
! 结构示意；坐标单位与参数顺序以官方 GDL Reference 为准
UI_DIALOG "柜体设置", 320, 240      ! 标题, 宽, 高
UI_PAGE "尺寸"
  UI_OUTFIELD "总宽", 10, 10, 70, 20
  UI_INFIELD  "w",    85, 10, 90, 20
  UI_OUTFIELD "总高", 10, 40, 70, 20
  UI_INFIELD  "h",    85, 40, 90, 20
UI_PAGE "门"
  UI_RADIOBUTTON "单扇", 10, 10, 80, 20
  UI_RADIOBUTTON "双扇", 10, 35, 80, 20
  UI_CHECKBOX    "加把手", 10, 70, 100, 20
```

三条排版原则：

1. 一页只放一件事（尺寸 / 门 / 细节），页签比长滚动好用
2. 左标签、右输入，x 坐标对齐成两列，别让眼睛来回跳
3. 高频参数放第一页左上角，低频的（材质、笔号）丢到最后一页

UI 脚本只管「显示和回写」，不参与建模：`UI_INFIELD "w"` 只是把控件绑到参数 `w`，真正拿 `w` 去画柜子的还是 3D 脚本。

::: warning 沙盒暂未支持参数表与 UI 脚本
沙盒只执行脚本里的变量和几何命令，`VALUES` / `PARAMETERS` / `UI_*` 都跑不了，写了会被当成未知命令。这一章的代码块是**结构示意**，请回 Archicad 的库部件编辑器验证；命令参数顺序也以官方手册为准，最快的对照方式是打开一个自带自定义面板的官方库部件，直接看它的 UI 脚本。
:::

## 常见坑

::: warning 三个高频错误
1. **脚本里写了描述名**：`BLOCK 总宽, d, h` 不认，脚本只认变量名 `w`
2. **`VALUES` 字符串忘了引号**：`VALUES "doorType" 单扇, 双扇` 会被当成两个未定义变量
3. **隐藏了还要用户填的参数**：`HIDEPARAMETER` 掉的参数永远保持默认值，别指望用户改
:::

## 练习

1. 给柜体的 `th`（板厚）加参数脚本约束：只允许 0.012 ~ 0.025，步长 0.001，并在板厚超过 0.02 时把层板数 `n` 限制在 1~3。
2. 用 UI 脚本的结构，把柜体的 5 个参数排成两页：第一页放 `w` / `h`，第二页放 `d` / `th` / `n`。

::: details 参考答案 1
```gdl
VALUES "th" 0.012, 0.025, 0.001
IF th > 0.02 THEN
  VALUES "n" 1, 3, 1
ELSE
  VALUES "n" 1, 6, 1
ENDIF
```
注意 `VALUES` 里的数字不带单位，单位由参数类型（`Length`）决定。
:::

::: details 参考答案 2
```gdl
UI_DIALOG "柜体设置", 300, 200
UI_PAGE "尺寸"
  UI_OUTFIELD "总宽", 10, 10, 70, 20
  UI_INFIELD  "w",   85, 10, 90, 20
  UI_OUTFIELD "总高", 10, 40, 70, 20
  UI_INFIELD  "h",   85, 40, 90, 20
UI_PAGE "板件"
  UI_OUTFIELD "总深", 10, 10, 70, 20
  UI_INFIELD  "d",   85, 10, 90, 20
  UI_OUTFIELD "板厚", 10, 40, 70, 20
  UI_INFIELD  "th",  85, 40, 90, 20
  UI_OUTFIELD "层板数", 10, 70, 70, 20
  UI_INFIELD  "n",   85, 70, 90, 20
```
每页的控件都从 `y = 10` 起算，坐标相对当前页，不是相对整个对话框。
:::
