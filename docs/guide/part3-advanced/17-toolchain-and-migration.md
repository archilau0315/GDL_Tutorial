# 第 17 章 工具链与版本迁移

> 图号 GDL-17 · 精通篇 · 阅读约 25 分钟 · 流程篇（无沙盒）

## 本章目标

- 说清库部件编辑器里每个脚本页的职责，以及「检查脚本」怎么用
- 用 `LP_XMLConverter` 把 GSM 拆成能进 git 的 XML
- 拿到一份升级 Archicad 版本时照着做的检查表
- 建立命名、版本号、发布与回滚的团队流程

## 编辑器里的七个位置

| 位置 | 作用 | 写错会怎样 |
|---|---|---|
| 参数表 | 名字、类型、默认值 | 脚本读到错误的值 |
| 主脚本 Master | 调用顺序的总控 | 3D/2D 不执行 |
| 3D 脚本 | 实体几何 | 3D 视图空 |
| 2D 脚本 | 平面符号 | 平面只剩一个热点 |
| 参数脚本 | 取值范围与联动 | 用户能填出崩坏的模型 |
| UI 脚本 | 自定义设置面板 | 功能在，但没人找得到 |
| 属性/附加脚本 | 属性导出与特殊工具 | 清单、标签取不到数据 |

写完立刻用**检查脚本**（Check Script）跑一遍：它不生成几何，只做语法与参数校验，报错比在 3D 窗口里瞎找快得多。

## GSM 与 XML：让对象能进 git

`.gsm` 是二进制容器，git 只能看出「变了」，看不出改了什么。Graphisoft 提供的 `LP_XMLConverter` 可以做往返转换：

```bash
# GSM → XML（可读、可 diff、可 review）
LP_XMLConverter libpart2xml cabinet.gsm ./src/cabinet

# XML → GSM（改完再打包）
LP_XMLConverter xml2libpart ./src/cabinet cabinet.gsm
```

| 做法 | 优点 | 缺点 |
|---|---|---|
| 只存 GSM | 简单，直接给 Archicad 用 | 无法 review，冲突无法合并 |
| 存 XML + 打包产物 | 改动可见、能分支、能回滚 | 多一步转换 |

团队做法：**XML 进 git，GSM 作为发布产物**（`dist/` 不入库）。参数名、脚本、UI 的每一次改动都能在 PR 里逐行看到。

## 升级检查表

Archicad 大版本升级时，库部件不会自动全对。按顺序过一遍：

1. **打开对象，看警告**：库部件编辑器顶部会列出弃用命令与参数冲突
2. **参数脚本先跑**：它是所有脚本里最先执行的，报错会连累整个对话框
3. **检查全局变量**：视图相关、项目相关的 `GLOB_*` 有没有被挪到不合适的脚本
4. **跑一遍检查脚本**：四个脚本各跑一次，别只看 3D
5. **换视图验证**：平面 1:100 / 1:50、剖面、3D、明细表各看一次
6. **重新生成 2D 符号**：平面表现变化最容易被忽略
7. **发布一次**：发布器（Publisher）里的清单字段最容易因属性改名而空白

::: warning 版本迁移的三个隐形杀手
1. **属性索引变化**：材质、填充的编号在不同版本可能重排，用名字比用编号稳
2. **默认值被覆盖**：迁移时参数默认值可能被新版本重置，先备份再迁移
3. **UI 脚本与旧参数界面混用**：同一对象别两套界面并存，用户会看到两套逻辑
:::

## 团队协作规范

| 项目 | 建议 | 原因 |
|---|---|---|
| 命名 | `KB_Cabinet_1200`：公司前缀 + 类型 + 主尺寸 | 库列表里能按前缀筛 |
| 版本号 | 用一个 `verMajor` / `verMinor` 参数，显示在 2D 符号角上 | 现场一眼看出用的是哪版 |
| 参数前缀 | `door_` / `win_` / `mat_` | 参数多时仍然可读 |
| 改前留档 | 每次发布打 tag，对应 XML 快照 | 出问题能精确回滚 |
| 谁改谁测 | 改动者负责跑完检查表 | 避免「我这儿是好的」 |

## 性能预算

同一个对象，写法不同，打开速度能差几十倍。给几个经验阈值：

| 项目 | 建议上限 | 超标怎么办 |
|---|---|---|
| 布尔运算 | 每对象 ≤ 5 次 | 用拼块或 `PRISM_` 代替 |
| 循环生成体块 | ≤ 200 个 | 远处用简化几何 |
| `PRISM_` 顶点 | 单段 ≤ 100 点 | 分段或用圆弧段数控制 |
| 2D 文本 | ≤ 50 处 | 合并成一段多行文本 |

原则：**细节级别（MVO）能省的面，一定省**。同一个对象在 1:200 的平面里不需要画把手。

## 常见坑

::: warning 三个高频错误
1. **只改 GSM 不入库 XML**：下次转换时改动被覆盖，白干
2. **升级后不重跑检查脚本**：语法通过但运行时参数错位，最难查
3. **用属性编号写死材质**：换项目、换版本编号就变了，用名字查找更稳
:::

## 练习

1. 把一个已有对象导出成 XML，用 git 提交，改一个参数名后再转回 GSM，确认改动只出现在 XML 的那一行。
2. 列出你手上最常见的 3 个对象，按上面的命名规范重新命名，并给每个加版本号参数。

::: details 参考答案 1
```bash
LP_XMLConverter libpart2xml old.gsm ./src/old
git add ./src/old
git commit -m "chore: 导入 old 的 XML 源"
# 改完参数名后
LP_XMLConverter xml2libpart ./src/old old_v2.gsm
```
`git diff` 应该只显示 `<Name>` 或 `<Parameter>` 的一行变化——如果整份 XML 都变了，说明转换器版本或编码不一致，先统一工具版本再提交。
:::

::: details 参考答案 2
```
KB_Desk_1400   verMajor = 1  verMinor = 0
KB_Door_Single verMajor = 2  verMinor = 1
KB_Window_0900 verMajor = 1  verMinor = 3
```
版本号参数不参与几何，只在 2D 符号角落用 `TEXT2` 打出来，方便现场核对。
:::
