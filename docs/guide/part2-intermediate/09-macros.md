# 第 9 章 宏与对象组织

> 图号 GDL-09 · 进阶篇 · 阅读约 20 分钟 · 含沙盒练习

## 本章目标

- 说清宏与 `GOSUB` 的本质区别
- 知道 `CALL "宏名"` 与 `PARAMETERS` 各自的角色
- 会按“一个宏只做一件事”拆分对象
- 有一套命名与调试顺序，能定位主对象还是子宏的问题

## 宏解决什么问题

宏（macro）是一个**独立的库部件**：有自己的参数、3D 脚本和 2D 脚本，可以被主对象调用，也可以被其它对象重复使用。

| 问题 | 全写在一个脚本 | 拆成宏 |
|---|---|---|
| 门扇、把手重复出现 | 复制粘贴，改一处漏三处 | 改子宏，所有调用一起更新 |
| 脚本越来越长 | 几百行，找不到位置 | 主对象只负责组装 |
| 别的对象也要用 | 再复制一份 | `CALL` 直接复用 |
| 单独测试零件 | 只能整体运行 | 子宏可单独打开调试 |

## CALL 与 PARAMETERS

调用入口是 `CALL "宏名"`，写法为 `CALL "宏名" PARAMETERS 参数名 = 值`。主对象与宏之间不共享变量，需要的数据显式传进去。

1. 参数名必须与宏定义一致，拼错不会自动纠正
2. 宏在自己的原点和坐标系里绘制，`CALL` 之前先用 `ADD` 定位
3. 宏有独立的脚本上下文，主对象的变量不会自动可见

::: warning 语法细节以官方手册为准
宏的定义块、参数声明以及 `PARAMETERS` 的完整写法，会随 Archicad 版本和对象类型变化。本章只讲调用思路与文件组织，不复制未核实的定义语法；动手前查官方 GDL Reference 的 Macro 章节。
:::

### CALL 不是 GOSUB

| | `GOSUB` | `CALL` |
|---|---|---|
| 范围 | 同一个脚本文件内跳转 | 调用另一个库部件 |
| 数据 | 共享全局变量 | 通过 `PARAMETERS` 显式传递 |
| 独立脚本 | 没有，只是代码段 | 有独立的 2D / 3D 脚本 |
| 沙盒 | 支持 | 不支持 |

## 示例一：主对象调用子宏（不可运行）

```gdl
! 【不可运行】真实 Archicad 写法，沙盒不支持 CALL
FOR i = 1 TO 2
  ADD (i - 1) * 0.42, 0, 0
  CALL "PRJ_Cabinet_Door" PARAMETERS doorWidth = 0.4, doorHeight = 0.7
  DEL 1
NEXT i
```

::: warning 沙盒会报“未知命令”
沙盒不识别 `CALL`。上面这段只说明调用结构，请勿直接粘进沙盒；练习请用下一节的 `GOSUB` 版本。
:::

## 示例二：用 GOSUB 模拟复用（可运行）

把“画一扇柜门”收进子程序，主程序调用两次：

```gdl
! 两只同样的柜门：GOSUB 复用“画一扇门”
dw = 0.4
dh = 0.7
FOR i = 1 TO 2
  ADD (i - 1) * (dw + 0.02), 0, 0
  GOSUB 200
  DEL 1
NEXT i
END

200:
MATERIAL 3
BLOCK dw, 0.02, dh
ADD dw - 0.06, -0.03, dh / 2
MATERIAL 5
SPHERE 0.02
DEL 1
RETURN
```

`dw`、`dh` 是共享变量，等于“隐式参数”。宏必须显式传参，所以这只是**教学类比，不是等价物**：沙盒能跑的只有 `GOSUB`。

## 文件组织

一个门窗类对象常见的拆分：

| 部件 | 职责 | 不该做什么 |
|---|---|---|
| 主对象 3D 脚本 | 读参数、算总尺寸、调用子宏、组装 | 不写大段重复几何 |
| 子宏：门扇 | 只画门扇 | 不改主对象参数 |
| 子宏：把手 | 只画把手 | 不假设安装位置 |
| 2D 脚本 / 符号 | 平面表达 | 不与 3D 尺寸脱节 |

### 命名规范

- 结构：`项目_类别_部件`，例如 `PRJ_Cabinet_Door`
- 只用字母、数字、下划线，不用空格和中文文件名
- 一个宏只做一件事；`_v2`、`_test` 只在临时文件里用，交付前清掉

### 调试顺序

1. 单独打开子宏，先确认它自己能画对
2. 检查参数默认值，别依赖主对象“碰巧”传对
3. 回到主对象，一次只加一个 `CALL`
4. 先把参数写死（如 `0.4`、`0.7`）锁定几何问题
5. 最后接回参数面板，逐个改值验证

## 常见坑

::: warning 三个高频错误
1. **在沙盒里试 `CALL`**：沙盒报未知命令，先用 `GOSUB` 练结构，真实调用回 Archicad 验证
2. **以为宏能看见主对象变量**：宏有独立上下文，需要什么就通过 `PARAMETERS` 传，否则拿到默认值或报错
3. **一个宏包办一切**：门扇、把手、玻璃、五金全塞进去等于没拆，一个宏只做一件事
:::

## 练习

**练习 1**：用两个 `GOSUB` 标签模拟“门扇宏”和“把手宏”，画两扇门。

::: details 答案
主程序只负责定位与调用，两个子程序各管一件事：

```gdl
FOR i = 1 TO 2
  ADD (i - 1) * 0.42, 0, 0
  GOSUB 500
  GOSUB 600
  DEL 1
NEXT i
END

500:
BLOCK 0.4, 0.02, 0.7
RETURN

600:
ADD 0.34, -0.03, 0.35
SPHERE 0.02
DEL 1
RETURN
```

把手子程序里的 `ADD` 要自己 `DEL`，否则返回后坐标会残留。
:::

**练习 2**：拿到一个新对象，怎样判断哪些部分该拆成宏？给出三条标准。

::: details 答案
1. **重复**：同一段几何出现两次以上，或别的对象也要用
2. **可独立测试**：这个零件能单独打开、单独看效果（门扇、把手、玻璃）
3. **参数边界清楚**：能列出不超过 5 个输入参数，且不依赖主对象的其它变量

三条都满足就适合拆；只有“重复”但参数纠缠不清，先理参数再拆。
:::
